## 背景（Context）

本仓库当前不存在任何 MCP 服务。我们希望以最小成本交付一个能被 MCP 客户端（例如 Claude Code）识别并调用的服务，实现"两数相加"。之所以需要一个单独的设计文档，是因为：

- 需要选择 Go 生态中合适的 MCP SDK；
- 需要确定传输层（stdio vs HTTP/SSE）；
- 需要设计工具入参的类型与边界行为（整数、浮点、溢出、缺参、非数值）。

约束条件：
- 使用 Go 语言实现。
- 工具链：Go 1.21 及以上。
- 运行环境：Windows 11（开发机为当前仓库所在机器），但二进制应可跨平台编译。
- 零外部运行态依赖（不依赖数据库、网络服务）。

## 目标 / 非目标

**目标：**
- 提供一个可执行的 MCP 服务端二进制，默认通过 stdio 对外通信。
- 注册一个 `add` 工具：输入两个数值 `a` 与 `b`，输出 `a + b`。
- 对非法输入（缺参、类型错误）返回结构化的 MCP 工具错误，而不是使进程崩溃。
- 提供一份可直接复制的 MCP 客户端注册示例。

**非目标：**
- 不支持除 `add` 以外的其他算术运算（减、乘、除等不在本次范围内）。
- 不引入 HTTP/SSE 传输（仅实现 stdio，后续如需可再扩展）。
- 不做鉴权、限流、日志持久化、指标上报等运维能力。
- 不提供图形界面或 HTTP 调试页。

## 关键决策（Decisions）

### 决策 1：使用 `github.com/mark3labs/mcp-go` 作为 MCP SDK
- **选择理由**：社区活跃度较高，API 稳定，支持 stdio 传输与工具注册，示例完整，能以最少代码量完成 MCP 服务搭建。
- **备选方案**：
  - 手写 JSON-RPC 2.0 + MCP 协议帧：工作量大、易错，不符合"最小示例"定位。
  - 其他第三方 Go MCP 库：当前生态中成熟度与文档完备度均不及前者。

### 决策 2：传输层使用 stdio
- **选择理由**：MCP 客户端（Claude Code、Claude Desktop 等）原生支持 stdio 拉起子进程；无需处理端口、证书、CORS 等问题；天然单用户、本地运行，安全面小。
- **备选方案**：HTTP/SSE——需要端口管理与鉴权，复杂度与本次目标不匹配。

### 决策 3：`add` 工具的入参类型使用 `number`（浮点）
- **选择理由**：MCP 工具参数经 JSON 传输，JSON 中的数字类型对应 Go 的 `float64`。用 `float64` 可同时覆盖整数与小数场景，避免为整型/浮点型分别注册两个工具。
- **边界处理**：
  - 当 `a` 或 `b` 缺失 → 返回 `invalid params` 错误。
  - 当 `a` 或 `b` 为非数值类型（如字符串、null）→ 返回 `invalid params` 错误。
  - 当 `a + b` 产生 `+Inf` / `-Inf`（极端溢出）或 `NaN` → 返回可计算结果字符串（保留 IEEE-754 语义），不视为错误，以保持实现简单。
- **备选方案**：强制整型（`int64`）——会在浮点输入时报错，使用体验不佳。

### 决策 4：返回值以文本形式呈现
- **选择理由**：MCP 工具响应标准通过 `content` 为 `text` 的方式返回，最兼容所有 MCP 客户端渲染。
- **格式**：使用 Go `strconv.FormatFloat(sum, 'f', -1, 64)` 输出最短精确表示，避免 `1 + 2 = 3.000000` 这类冗余格式。

### 决策 5：单文件布局
- **选择理由**：本次功能极其简单，拆包会带来更高的心智成本；单个 `main.go` + `go.mod` 即可，便于阅读与复制。
- **未来扩展**：若后续新增多个工具，再按 `internal/tools/<name>/` 拆分。

## 风险与权衡（Risks / Trade-offs）

- **风险**：SDK `mark3labs/mcp-go` 在未来版本可能发生 API 破坏性变更。
  **缓解**：在 `go.mod` 中锁定具体版本号（使用 `go get` 拉取后提交 `go.sum`）。
- **风险**：`float64` 对超过 2^53 的整数精度不足（会丢精度）。
  **缓解**：在工具描述中注明"适用于 ±2^53 以内的数值"。本示例定位为演示用途，不额外引入任意精度库（如 `math/big`）。
- **权衡**：仅支持 stdio，无法被纯 HTTP 场景的客户端调用。
  **接受**：本次定位为本地工具，HTTP 场景不在目标内。
- **风险**：Windows 下构建产物为 `.exe`，MCP 客户端配置示例需对应调整路径。
  **缓解**：在 README 片段或 tasks 中的"客户端注册"步骤里明确 Windows / macOS / Linux 各自的路径示例。
